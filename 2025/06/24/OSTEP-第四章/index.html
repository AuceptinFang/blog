第二题

现在用这些标志运行：./process-run.py -l 4:100,1:0。这些标志指定了一个包含 4 条指令的进程（都要使用 CPU），并且只是简单地发出 I/O 并等待它完成。完成这两个进程需要
多长时间？利用-c 检查你的答案是否正确。

两个进程，第一个4指令无io，4时钟周期，另一个是一个io指令

 # python ./process-run.py -l 4:100,1:0

Important behaviors:
  System will switch when the current process is FINISHED or ISSUES AN IO

也就是说一个io需要发起异常、完成两个时间周期，以及一个io操作？

第四题

现在探索另一些标志。一个重要的标志是-S，它决定了当进程发出 I/O 时系统如何
反应。将标志设置为 SWITCH_ON_END，在进程进行 I/O 操作时，系统将不会切换到另一
个进程，而是等待进程完成。当你运行以下两个进程时，会发生什么情况？一个执行 I/O，
另一个执行 CPU 工作。（-l 1:0,4:100 -c -S SWITCH_ON_END）

阻塞了调度呗

# python ./process-run.py -l 1:0,4:100 -c -S SWITCH_ON_END

  1         RUN:io         READY             1
  2        BLOCKED         READY                           1
  3        BLOCKED         READY                           1
  4        BLOCKED         READY                           1
  5        BLOCKED         READY                           1
  6        BLOCKED         READY                           1
  7*   RUN:io_done         READY             1
  8           DONE       RUN:cpu             1

 10           DONE       RUN:cpu             1
 11           DONE       RUN:cpu             1

没有问题，io操作的阻塞期间没被调度走

第七题

现在运行相同的进程，但使用-I IO_RUN_IMMEDIATE 设置，该设置立即运行发出
I/O 的进程。这种行为有何不同？为什么运行一个刚刚完成 I/O 的进程会是一个好主意？

现在的策略是io结束了控制就回到pid 0继续，这样每一个io的阻塞期间都有进程运行，cpu得到了充分利用。

至于为什么运行一个刚刚完成 I/O 的进程会是一个好主意，如果认为程序有良好的局部性在一次io之后接着io的可能性比较大，那么考虑到io操作较长时间的阻塞，把其它cpu操作尽可能放在阻塞期间执行显然是好主意
